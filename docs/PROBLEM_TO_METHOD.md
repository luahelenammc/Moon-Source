# Find the Moon Source method for your problem

This is a **reader's route**, not a new capability, second registry or replacement for canonical methods. Start with a situation you recognize, try the smallest move, and inspect the result. Each entry below points to the existing authority. No app, LLM, memory, tool, connector or external permission is installed by reading it.

**How to use:** open the linked canonical body in an AI with actual retrieval access (or paste/attach its text). Supply only authorized context. Ask for the first move described here and verify the resulting artifact or decision. If you are developing a product, translate the method into your own tested workflow and access controls.

## Find a fit among the 16 current public capabilities

The situations are fictional examples, not real clients or claims of measured results. You usually need **one** method, not all sixteen.

### Understand requests and people

| Your situation | Method / canonical source | First move | What to check and what it does not prove |
|---|---|---|---|
| A request contains corrections, context and several possible deliverables. | <!-- problem-route: preflight --><a id="preflight"></a>[Preflight](../portables/preflight/PREFLIGHT.md) | Restate the intended outcome, what must be preserved and what needs approval before acting. | **Inspect:** One faithful task brief and any consequential unanswered question. **Limit:** It does not guess hidden intent or authorize execution. |
| The same project decisions must be repeated in every new AI conversation. | <!-- problem-route: moon-source-setup --><a id="setup"></a>[Setup](../portables/setup/MOON_SOURCE_SETUP.md) | Identify a small project context, its governing source and when to update it. | **Inspect:** A minimal context setup, ownership, update trigger and first test. **Limit:** It does not install memory or make every personal detail persistent. |
| A reply from a colleague sounds ambiguous and you want to answer without overreacting. | <!-- problem-route: be-my-eyes --><a id="be-my-eyes"></a>[Be My Eyes](../portables/be-my-eyes/BE_MY_EYES.md) | Read the interaction as a scene: observation, relationship, possible reception and overread. | **Inspect:** A proportionate response posture grounded in what is known. **Limit:** It cannot reveal the colleague's motive or guarantee their reaction. |
| Several weak indicators suggest a project is slipping, but no single signal proves it. | <!-- problem-route: signal-calibration --><a id="signal-calibration"></a>[Signal Calibration](SIGNAL_CALIBRATION.md) | Separate observations, dependent cues, leading inference, meaningful alternative and update condition. | **Inspect:** A working interpretation with explicit evidentiary floor and uncertainty. **Limit:** Plausible inference is not a verified fact, diagnosis or probability score. |

### Govern sources and knowledge

| Your situation | Method / canonical source | First move | What to check and what it does not prove |
|---|---|---|---|
| An AI found a policy document, but you do not know if it is the current approved one. | <!-- problem-route: connected-sources --><a id="connected-sources"></a>[Connected Sources](CONNECTED_SOURCES.md) | Check actual connector reach, source authority, last revision and read scope. | **Inspect:** A source reference with freshness and access limitations, or a truthful fallback. **Limit:** Reachability is not authorization, completeness or write permission. |
| Several project files give different answers and an old summary still appears current. | <!-- problem-route: source-hygiene --><a id="source-hygiene"></a>[Source Hygiene](SOURCE_HYGIENE.md) | Audit stale authority, duplication, conflicting claims and missing owners before editing. | **Inspect:** A bounded diagnosis with the smallest proposed correction and its owner. **Limit:** It is not an automatic corpus repair or a substitute for source review. |
| A long-running repository has folders inherited from earlier work that no longer match its responsibilities. | <!-- problem-route: semantic-reweave --><a id="semantic-reweave"></a>[Semantic Reweave](SEMANTIC_REWEAVE.md) | Temporarily ignore folder names and regroup content by meaning, function and governing authority. | **Inspect:** A proposed current/latent topology comparison and only the justified moves. **Limit:** A new folder structure is not automatically better or authorized. |
| A meeting changed a real decision, but nobody knows whether to summarize it or update the source of truth. | <!-- problem-route: source-operations --><a id="source-operations"></a>[Source Operations](SOURCE_OPERATIONS.md) | Classify the operation as retrieve, process, metabolize or promote; seek authority before mutation. | **Inspect:** Either a working interpretation, a minimal sovereign patch with readback, or no change. **Limit:** Processing alone never silently writes; novel ideas do not become public methods by naming them. |
| A project handoff between teams loses source references, exceptions and uncertainty. | <!-- problem-route: moon-source-language --><a id="moon-source-language"></a>[Moon Source Language](../portables/msl/MOON_SOURCE_LANGUAGE.md) | Specify the recipient, governing source, what meaning must travel and what must stay out. | **Inspect:** A bounded handoff with provenance, claims and a recipient-facing readback. **Limit:** A structured packet does not transfer permission or execute the handoff. |

### Organize work and reuse

| Your situation | Method / canonical source | First move | What to check and what it does not prove |
|---|---|---|---|
| A shared folder contains incoming files, pending reviews and approved work without anyone knowing which is which. | <!-- problem-route: lifecycle-workspace-router --><a id="lifecycle-workspace-router"></a>[Lifecycle Workspace Router](LIFECYCLE_WORKSPACE_ROUTER.md) | Keep source-of-record, lifecycle, assignee, revision and file location as separate dimensions. | **Inspect:** An intake/action/status view pointing to the original source with a verifiable review state. **Limit:** A folder or dashboard position is not proof of approval, authorship or task assignment. |
| A guide is adapted and translated by different contributors, and its origin gets lost. | <!-- problem-route: credits-attribution-ops --><a id="credits--attribution-ops"></a>[Credits & Attribution Ops](CREDITS_ATTRIBUTION_OPS.md) | Record identity, author, canonical source, transformations, permissions and disclosure boundary. | **Inspect:** A compact lineage and attribution record that travels with the derived material. **Limit:** Recording credit does not establish ownership or grant a missing license. |
| A team repeats a useful review checklist differently in every project. | <!-- problem-route: procedural-projection --><a id="procedural-projection"></a>[Procedural Projection](PROCEDURAL_PROJECTION.md) | Extract the stable trigger, sequence, stop line, output and QA, leaving live facts in their sources. | **Inspect:** A reusable procedure or skill specification that references the governing source. **Limit:** Documentation is not an installed skill or proof that the procedure will execute. |

### Execute, verify and learn

| Your situation | Method / canonical source | First move | What to check and what it does not prove |
|---|---|---|---|
| A large task wastes expensive reasoning on repetitive extraction and repeats the same context across handoffs. | <!-- problem-route: adaptive-orchestration --><a id="adaptive-orchestration-protocol"></a>[Adaptive Orchestration Protocol](../portables/adaptive-orchestration/ADAPTIVE_ORCHESTRATION_PROTOCOL.md) | Separate the decision bottleneck from bulk work; choose available surface, model effort and delegation proportionally. | **Inspect:** An execution plan with acceptance checks and total-work tradeoffs. **Limit:** It does not unlock unavailable models, agents, budgets or execution rights. |
| A recurring review must run in a specific browser or workflow with visible checkpoints. | <!-- problem-route: operational-devices --><a id="operational-devices"></a>[Operational Devices](OPERATIONAL_DEVICES.md) | Define the concrete surface, trigger, inputs, authorization, dry-run, stop conditions and receipt. | **Inspect:** A bounded device contract and evidence of what actually ran on that surface. **Limit:** The contract does not provide the browser runtime or unrestricted tools. |
| A deployment or data update fails halfway and retries keep hiding the actual failure. | <!-- problem-route: operational-reliability --><a id="operational-reliability"></a>[Operational Reliability](OPERATIONAL_RELIABILITY.md) | Check target, instrument, dependencies and scope before the smallest reversible retry. | **Inspect:** A diagnosis, bounded action, before/after receipt and recovery path. **Limit:** A new error or tool log does not by itself prove success. |
| The same handoff mistake keeps resurfacing after individual fixes. | <!-- problem-route: failure-foundry --><a id="failure-foundry"></a>[Failure Foundry](FAILURE_FOUNDRY.md) | Collect safe evidence, isolate failure domain, fix the case and test a transferable micro-rule. | **Inspect:** A tested checklist, gate or procedure candidate, or a situated lesson only. **Limit:** One failure does not automatically justify a universal new capability. |

## Compositions for real project shapes

These are **invented examples** showing when a second method earns its place. The method names are not a compulsory pipeline.

| Project situation | Methods and conditions for combining them | Evidence to check / limitation |
|---|---|---|
| A learning program spanning several sessions | The person returns after a break and the operational module has changed. Start with [Conversational Context](CONVERSATIONAL_CONTEXT.md) to select only the approved purpose-bound state, compare the authorized earlier step with the current program record and distinguish a human-review recommendation from an actual delivered referral. Bring in [Connected Sources](CONNECTED_SOURCES.md) only if the host can access a legitimate current system. If a durable project setup is also needed, use [Setup](../portables/setup/MOON_SOURCE_SETUP.md). | the current approved step, excluded old fields, uncertainty and unsent handoff status. No explanation for the absence is inferred. |
| A volunteer team whose responsibility shifts | A submission reaches a shared folder but no reviewer has accepted it. Use [Lifecycle Workspace Router](LIFECYCLE_WORKSPACE_ROUTER.md) for source-of-record, lifecycle, action and revision; [Source Operations](SOURCE_OPERATIONS.md) enters only for an authorized update. Use [Credits & Attribution Ops](CREDITS_ATTRIBUTION_OPS.md) only if the submitted document has material origin or reuse concerns. | one source pointer, an explicit assigned action, and a verified revision-bound review stamp. Folder location alone is not approval. |
| A knowledge base gives conflicting answers | A fresh API note and an older guide disagree. Start with [Source Hygiene](SOURCE_HYGIENE.md) to identify stale authority and duplication. Use [Semantic Reweave](SEMANTIC_REWEAVE.md) only if the corpus's *structure* itself is wrong, not merely one outdated paragraph. If a patch is authorized, use [Source Operations](SOURCE_OPERATIONS.md) with readback; repeated failure may justify [Failure Foundry](FAILURE_FOUNDRY.md). | the authoritative fact, the minimal change, and whether an actual readback occurred. |

## How to tell if the method helped

Before expanding to a second module, check: *Did we make a material distinction that was missing? Can another person inspect the outcome? Does it still point to its governing source? Do we know what has not been executed or proved?* If nothing changed, prefer plain language and existing project tools.

For app-specific implementations, see [For AI Builders](FOR_AI_BUILDERS.md) and [From Method to Implementation](FROM_METHOD_TO_IMPLEMENTATION.md). The [Evidence and Claims](../EVIDENCE_AND_CLAIMS.md) boundary applies to every illustrative example. In particular, a described workflow is not a deployed integration.
