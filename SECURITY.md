# Security Policy

Moon Source is a public context-architecture reference body with executable repository tooling. This policy covers the scripts, validators, packaging helpers, CI configuration and public artifacts in this repository.

## Report a security issue

Use the public project contact, [LuaHelenaMMC@gmail.com](mailto:LuaHelenaMMC@gmail.com), with a concise description and a minimal reproduction when one is safe to provide. Do not attach private corpora, credentials, API keys, access tokens, patient or institutional data, or other confidential material. Prefer synthetic examples and describe the affected path, command, revision and observed behavior.

Report issues such as unintended code execution, unsafe file or network behavior, credential or secret exposure, packaging tampering, or CI/repository permission problems as security concerns. A disagreement about method, wording, licensing or architecture belongs in the ordinary contribution or proposal path instead.

There is no bug bounty or guaranteed response timeline. The project does not claim to have received an independent security audit or certification. Executable scripts are the main software attack surface; documentation and methods should still be reviewed against the [public boundary](PUBLIC_BOUNDARY.md) and [licensing contract](LICENSING.md).

For contribution and maintainer routing, see [CONTRIBUTING.md](CONTRIBUTING.md) and [MAINTAINERS.md](MAINTAINERS.md).
