# Operational Reliability

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/OPERATIONAL_RELIABILITY.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/OPERATIONAL_RELIABILITY.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the intended operation, environment, available evidence, reversibility and risk. Infer what the context supports, ask only material questions, and mark missing evidence.

Inspect before mutation; identify failure modes and recovery; minimize the authorized change; record a proportionate receipt, freshness and readback; reconcile observed state and report unresolved failures. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a safe execution or diagnostic result supported by receipts. Do not invent successful actions or require elaborate machinery for trivial work. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
