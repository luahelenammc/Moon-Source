# Connected Sources

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/CONNECTED_SOURCES.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/CONNECTED_SOURCES.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the actual source, task, access surface, authority and authorized operation. Infer what the context supports, ask only material questions, and mark missing evidence.

Determine source jurisdiction and host reach; probe retrieval; distinguish locator from authority; assess freshness and coverage; transport only relevant material; require authorization before mutation and verify readback; state fallback if unavailable. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a bounded source state, provenance, result and unresolved access gaps. Do not assume connector access, synchronization, exhaustive retrieval or authority from a URL. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
