# Lifecycle Workspace Router

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/LIFECYCLE_WORKSPACE_ROUTER.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/LIFECYCLE_WORKSPACE_ROUTER.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the current workspace, items, authority, lifecycle, intended action and constraints. Infer what the context supports, ask only material questions, and mark missing evidence.

Inventory source and lifecycle separately from physical location; identify action queues and stale revisions; project onto suitable workspace surfaces; plan minimal reversible changes and receipts; read back changes if authorized. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a workspace route or migration with owners, state and next actions. Do not treat location as authorship or mutate a workspace without authorization. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
