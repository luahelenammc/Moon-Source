# Source Hygiene

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/SOURCE_HYGIENE.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/SOURCE_HYGIENE.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the project scope, accessible source inventory, use case and mutation permissions. Infer what the context supports, ask only material questions, and mark missing evidence.

Inventory actual sources and distinguish authority from reach; check freshness, duplicates, conflicts and orphaned decisions; assess provenance and consequences; propose the smallest safe repair and verify any authorized changes. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a prioritized diagnosis, evidence and repair plan or verified patch. Do not remove sources or settle conflicting claims merely by averaging. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
