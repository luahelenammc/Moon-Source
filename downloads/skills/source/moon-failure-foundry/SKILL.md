# Failure to Capability — Failure Foundry

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/FAILURE_FOUNDRY.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/FAILURE_FOUNDRY.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use failure evidence, desired behavior, context, constraints and current mechanisms. Infer what the context supports, ask only material questions, and mark missing evidence.

Reconstruct repeatable failure and causal layer; distinguish isolated noise from a pattern; select the smallest intervention; define trigger, guardrail and regression tests; promote only when evidence supports reuse. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a bounded candidate mechanism with validation and lifecycle state. Do not claim autonomous improvement, causal proof or a universal promotion rule. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
