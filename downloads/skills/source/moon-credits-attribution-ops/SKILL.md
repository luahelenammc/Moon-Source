# Credits & Attribution Ops

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/CREDITS_ATTRIBUTION_OPS.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/CREDITS_ATTRIBUTION_OPS.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use source materials, authorship evidence, permissions and intended reuse. Infer what the context supports, ask only material questions, and mark missing evidence.

Trace origin, authorship, canonicality and transformation; separate permissions, donor boundaries and uncertainty; preserve records and proportionate attribution; audit claims and resolve conflicting evidence before release. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a provenance and attribution record, uncertainties and unresolved permissions. Do not adjudicate ownership or licensing as a legal authority. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
