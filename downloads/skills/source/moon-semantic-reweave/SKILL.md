# Semantic Reweave

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/SEMANTIC_REWEAVE.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/SEMANTIC_REWEAVE.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the corpus, source authority, current usage, proposed destination and scope. Infer what the context supports, ask only material questions, and mark missing evidence.

Map responsibilities and semantic relationships; compare them to existing containers; classify mismatches and collisions; design the smallest authority-preserving repair; preserve provenance and validate readback if authorized. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a structural diagnosis and bounded repair or plan. Do not move or delete material solely for tidiness, or treat inferred structure as proven. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
