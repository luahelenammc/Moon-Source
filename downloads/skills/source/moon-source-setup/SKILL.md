# Moon Source Setup

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/portables/setup/MOON_SOURCE_SETUP.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/portables/setup/MOON_SOURCE_SETUP.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the person’s practical goal, current sources, available environment, permissions and continuity needs. Infer what the context supports, ask only material questions, and mark missing evidence.

Elicit only decision-relevant context; inspect authorized existing material; distinguish personal, project, persistent and transfer needs; choose the smallest usable setup; preserve user ownership and verify the first useful result. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a practical setup, ownership and next step, with limitations. Do not force a large architecture, claim persistence or require a product-specific host. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
