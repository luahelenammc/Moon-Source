## Inputs and procedure

Use the job, environment, authority, state, failure modes and acceptance criteria. Infer what the context supports, ask only material questions, and mark missing evidence.

Identify the procedure and execution surface; define inputs, state, allowed operations, guards, outputs and receipts; test failure and fallback; keep device, source and actual execution distinct. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a device contract with execution and verification boundaries. Do not claim a device is installed, active or effective solely because it was documented. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
