# Moon Source Language

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/portables/msl/MOON_SOURCE_LANGUAGE.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/portables/msl/MOON_SOURCE_LANGUAGE.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the object, intended destination, jurisdiction, provenance and audience. Infer what the context supports, ask only material questions, and mark missing evidence.

Reconstruct meaning and authority first; select the smallest MSL structure that preserves distinctions, provenance and continuity; carry exclusions and unresolved uncertainty; verify that rendering has not altered substance. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a proportionate structured artifact with its source and boundaries. Do not use formatting as a substitute for truth or invent authority and facts. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
