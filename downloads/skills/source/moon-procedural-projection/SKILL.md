# Procedural Projection

## Source and scope

This skill projects the public Moon Source method into an executable entry point. Read `references/source/docs/PROCEDURAL_PROJECTION.md` before substantive work and follow its decision rules, outputs, boundaries and linked supporting references. This bundled copy is a versioned snapshot; consult https://github.com/luahelenammc/Moon-Source/blob/main/docs/PROCEDURAL_PROJECTION.md when freshness matters or a revision may have superseded it. When unavailable, identify the snapshot and bound claims. See `references/PROVENANCE.json` for source hashes and link-only adaptations.

## Inputs and procedure

Use the canonical method, target surface, actual job, audience and constraints. Infer what the context supports, ask only material questions, and mark missing evidence.

Resolve source authority and scope; extract stable triggers, decisions, outputs, guards and tests; map source to projection; preserve provenance and freshness; test recoverability and update behavior. Apply the branches and guardrails in the canonical reference rather than treating this concise router as the full method.

## Output and safeguards

Return a procedure and traceable coverage with explicit exclusions. Do not conflate a snapshot or projection with the governing source or live state. Respect user authorization, source jurisdiction and privacy. If access, capability, source or permission is absent, report the limitation and return the smallest useful result; never claim a write or execution that was not observed. Separate source facts, inference and current state. Check the result against the canonical method's own QA and claims.
