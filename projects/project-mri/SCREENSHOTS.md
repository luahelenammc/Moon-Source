# Screenshot and recording plan

The capture set should make the demo legible without private context or live integrations. Capture at a readable browser width with the synthetic corpus already reset.

## Seven frames

1. **Hero / Start** — product name, Open Source track, problem statement and the “proposal-only” boundary.
2. **Project map** — document, object, finding-family and before/after counts plus inventory table.
3. **Contradiction evidence** — storage contradiction expanded with both paths, line ranges and quotes.
4. **Authority** — extracted decision table showing current candidate, owner and authority fields.
5. **Blueprint** — governing candidates, historical sources and unresolved human decisions.
6. **Review** — one approved intent, one rejected/deferred item and `mutation_applied: false`.
7. **Before / after + export** — fixed question, observable metrics and report download control.

## Capture constraints

- synthetic data only;
- no account identifiers, tokens or private paths;
- no provider/GPU claim in the frame;
- keep one evidence quote visible in the contradiction frame;
- capture after reset for a clean initial state;
- retain the raw report and `northstar_eval.json` beside the final images.

The repository also includes [`assets/mri-pipeline.svg`](assets/mri-pipeline.svg) and [`assets/mri-hero.svg`](assets/mri-hero.svg) as stable fallback visuals. They are diagrams/briefing art, not fabricated runtime screenshots.
