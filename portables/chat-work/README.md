# 🔀 Chat–Work Routing Protocol

**Route a task across Chat, Work and Codex by the object being changed, the workload required and the intelligence budget available.**

[▶️ Start here](CHAT_WORK_ROUTING_PROTOCOL_V4.md#first-use) · [⬇️ Download package](../../downloads/chat-work-routing-protocol-v4.zip) · [🌙 Moon Source](../../README.md)

## Use this when

- a task may need to move between conversational reasoning and sustained execution;
- you need to choose surface, model/reasoning effort and source transport separately;
- a Work result must return to Chat for verification and bounded closure;
- expensive execution needs a survivability check before spending the budget.

## What it does

Chat–Work defines an object-routed execution loop across Chat, Work and Codex, including execution profiles, connector-aware source transport, Budget Survivability, the Intelligence Distillation Ladder and Chat Postflight.

## What it does not do

It does not itself create access to a model, tool, connector or execution surface. Product names, limits and availability are date-sensitive and must be rechecked when they matter.
