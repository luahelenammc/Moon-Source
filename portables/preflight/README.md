# Preflight

*Human Intent Reconstruction Before AI Execution*

Preflight is the Moon Source portable for reconstructing what a person is actually trying to accomplish before an AI acts on the literal wording of their message. The current portable version is **2.0**.

> Humans should not have to prompt like machines.

## First use

Preflight is a standalone instruction portable for the moment when a request is conversational, incomplete, messy or easy to misunderstand. It helps the AI recover the intended outcome before execution; it does not install a runtime or require the full Moon Source repository.

For repository-wide orientation, return to [Moon Source first use](../../README.md#first-use).

### Nothing is installed

Reading or pasting [`PREFLIGHT_V2.md`](PREFLIGHT_V2.md) does not create a global behavior, hidden memory, permission or product mode. The canonical body is the semantic authority; this README explains how to begin with it.

### Say this first

Open the canonical portable and use the shortest command that matches your need:

```text
Preflight
```

Useful variants are:

```text
Silent Preflight
Preflight only
Show reconstructed task
Deep Preflight
```

For a normal first run, say:

```text
Use Preflight before acting.
Reconstruct my intended outcome, corrections and constraints in ordinary language.
Show me the task you would execute, then wait for my approval if the action is consequential.

Request: [say what you need in your own words]
```

### What happens next

The AI should identify the likely outcome, what needs correction, relevant constraints, material unknowns and the next action. It should ask only for missing information that changes the result and keep authority, risk, freshness or mutation checks proportionate to the consequence.

The portable works alone from the request and any material you supply. The full repository adds optional routes for source governance, Field to Form, operational reliability, lineage and other consequence-sensitive work; it does not become a prerequisite.

### Minimal example: a messy request

Instead of turning this into a machine-style prompt:

> “Can you update the thing from last week, keep the tone, fix what she meant, and send it if it looks right?”

say:

```text
Preflight only.
Reconstruct the intended outcome, what “the thing” probably refers to,
which tone must be preserved, what “she meant” still leaves uncertain,
and whether sending is authorized. Do not edit or send yet.
```

The useful result is a short reconstructed task with explicit unknowns, not an invented certainty.

### Manual actions and boundary

You may need to identify the referenced file, paste a missing thread, approve the reconstructed task, choose the destination or perform the final send yourself. Preflight cannot publish, send, switch a product surface or perform an unavailable action unless the current environment explicitly exposes it and you authorize it.

For consequential tasks, approve the reconstructed task before an external write or other irreversible step.

### What this portable does not claim

- It does not read hidden thoughts or know intent with certainty.
- It does not guarantee how another person will react.
- It does not permanently change ChatGPT or install a global behavior.
- It does not replace professional judgment, evidence or explicit authorization.
- It is not a formal specification of every future request.

### Troubleshooting

If the response becomes too architectural, say:

```text
Preflight only. Use ordinary language.
Reconstruct my intended outcome, corrections and constraints in a few lines,
then stop. Do not load the whole Moon Source repository.
```

If the reconstruction is wrong, correct the outcome or constraint directly and ask the AI to update the working task. If you only need a quiet internal check, use `Silent Preflight`; if you want to inspect the reconstruction without execution, use `Show reconstructed task`.
