# Moon Source Setup — First-Use Guide

_Read this before using the Setup portable._

## What this is for

Moon Source Setup is the smallest portable for giving an AI proportionate context about a person, project or working environment. It helps the AI inspect what is already present, diagnose what is missing or stale, preserve useful structure and choose the smallest setup that can carry the need.

You do not need to know Moon Source vocabulary before starting.

## Nothing is installed

Setup is an instruction layer, not an application, memory service, hosted data store or automatic settings change. Reading `MOON_SOURCE_SETUP.md` does not create persistent memory or connect a source.

A persistent-source route is available only when the current product actually exposes an authorized, reachable source and the human approves its use. If it is unavailable, use the standalone route from material you provide.

## Provide this canonical file

Use the canonical body [MOON_SOURCE_SETUP.md](MOON_SOURCE_SETUP.md). This [root FIRST_USE.md](../../FIRST_USE.md) explains how to begin; it does not replace or override the canonical method.

If you received a package, keep these roles distinct:

- `MOON_SOURCE_SETUP.md` is the semantic body;
- `README.md` is family orientation;
- `FIRST_USE.md` is onboarding and boundary guidance.

## Say this first

The shortest start is:

~~~text
Execute.
~~~

For a more explicit run:

~~~text
Use Moon Source Setup for this task.
Inspect what context already exists, diagnose the smallest useful setup,
preserve what should remain authoritative, and propose the next proportionate step.

Need: [describe the person, project or context problem]
~~~

## What happens next

The AI should first understand the need, inspect any material actually available, separate current context from missing context, and choose a proportionate result. It may recommend a lightweight profile, handoff, source, repair or one small test. Repository-aware work is optional; no full-repository load is implied.

The portable's persistent-source probe should remain a probe. It must not pretend that a connector, memory layer or durable write exists when the current environment has not exposed one.

## Minimal example

You have project notes scattered across messages and want an AI to use them without receiving a giant, undifferentiated prompt.

Provide `MOON_SOURCE_SETUP.md` and say:

~~~text
Use Moon Source Setup.
Need: help me organize the current notes for this project into the smallest
useful context source, while preserving uncertainty and telling me what I
would need to save manually.
~~~

A useful result may be a proposed context source plus one test. It is not automatically saved anywhere.

## Manual actions and unavailable capabilities

You may need to paste or attach the source material, choose a destination, authorize a connector, approve a write, save the result or run a follow-up test. Setup cannot grant persistence, connectors, account access, model changes or product memory.

If a source is claimed to be current, verify the locator and readback through the capability actually available. A recommendation is not evidence that the action occurred.

## What this portable does not claim

- It is not a hosted Moon Source service or universal profile generator.
- It does not guarantee cross-session memory or durable context.
- It does not silently connect to Drive, GitHub or another source.
- It does not require the whole repository for an ordinary setup task.
- It does not replace human authority over personal, project or organizational context.

## Troubleshooting

- **Need a quick answer:** provide only the canonical file and the immediate need.
- **Repairing an existing context:** say `Use Repair mode` and identify the material that may be stale, duplicated or contradictory.
- **No connector is available:** say `Use the standalone route` and provide the material directly.
